# README 案例对比设计

## 目标

在中文 README 中加入四组案例库图片对比，让读者快速理解同一提示词再次生成时，在结构、文字、材质和画面组织上的表现变化，并引导读者进入 GPT Image 2.5 专区查看交互式对比与完整生成记录。

## 展示位置与结构

新章节放在“项目定位”之后、“页面入口”之前，避免打断安装与开发说明。

章节包含：

1. 一段口径说明，区分案例库原图与 Codex 内置生图的首次复现结果。
2. 四组并排图片，每组使用两列表格；图片设置 `width="100%"`，不使用固定像素宽度。窄屏仍保留双列对照，图片可点击打开原文件查看细节，验收时确保页面没有由图片固定宽度导致的横向溢出。
3. 每组补充案例编号、观察重点和基于现有生成记录的差异说明。
4. 末尾使用完整本地地址 `http://localhost:5173/gpt-image-2-5/`，承接完整参数、来源和滑动对比，避免 GitHub 将站点根路径解析成仓库外链接。

## 案例选择

- 案例 #532，柠檬饮料六格广告：观察多面板结构、人物一致性、品牌文字和指令遵循。
- 案例 #527，里约纸雕旅行海报：观察立体层次、地标、票据文字和纸张材质。
- 案例 #523，曼哈顿公园水彩插画：观察水彩笔触、前后景层次、人物和无字约束。
- 案例 #510，Bichon Shop 应用图标：观察圆角轮廓、留白、毛发材质和品牌文字。

## 事实口径

- 左侧统一称为“案例库原图”，不声称其原始模型已被独立核验为 GPT Image 2。
- 右侧统一称为“同提示词首次复现”，并注明由 Codex 内置生图完成。
- 不声称右侧具体模型 ID、质量档位或费用，因为工具未返回这些信息。
- “优化”只描述图片中可观察到的变化，不给出无数据支撑的整体性能结论。
- 同时保留偏差说明，例如额外品牌区、未严格执行的元素、底色或字体变化。

## 资源引用

- 原图使用 `data/images/case{编号}.jpg` 的相对路径。
- 复现图使用 `src/assets/image25-case{编号}-run1.png` 的相对路径。
- 不复制、不压缩、不改写现有图片，避免新增重复资源。

## 验证

- 检查 README 中八个图片路径均存在。
- 检查四组标题、编号和说明与 `src/image25/realCases.js`、`src/image25/additionalCases.js` 一致。
- 执行 Markdown 链接与图片引用检查。
- 专项检查事实口径：不得把案例库原图写成已核验的 GPT Image 2 产物，不得补写复现图的具体模型、质量档位或费用，所有“优化”结论必须限定为图片中可观察到的差异。
- 运行 `npm run validate:cases`，确认文档改动未影响案例数据。
- 在 GitHub 风格 Markdown 预览中检查桌面和窄屏可读性，确认双列图片使用流式宽度且不会因固定宽度产生横向溢出。
