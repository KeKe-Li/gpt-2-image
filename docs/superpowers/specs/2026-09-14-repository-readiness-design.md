# 仓库可提交性与链接完整性修复设计

## 目标

让当前项目的必要文档、CI 配置、测试和环境变量示例可以进入版本控制，并把“当前产品仓库”与“原始来源仓库”拆成两个清晰概念，消除案例、模板和来源说明断链。

## 仓库模型

- 当前仓库：`https://github.com/KeKe-Li/gpt-2-image`，用于站点、安装命令、案例链接、模板链接和包元数据。
- 原始来源：见仓库根目录的 `UPSTREAM.md`（仅用于溯源、来源 manifest 与来源更新审查脚本）。
- 原始固定基线继续使用 `073d105d4dbb3f3afcd2e7cd194cee3a557b0999`，不伪造当前仓库提交。

## 文件可提交性

`.gitignore` 只忽略本地环境、构建产物、依赖和工具缓存，不再忽略 `docs/`、`.github/`、测试目录和 `.env.example`。必要文档必须同时满足：本地存在、没有被 Git ignore、被 README 或生成数据引用时路径可解析。

## 来源说明

新增根目录 `UPSTREAM.md`，记录原始来源、固定提交、许可证、导入完整性和当前项目的独立改动。`data/upstream-manifest.json` 分成 `project` 与 `source`，审查脚本只读取 `source`。

## 验证

- 仓库完整性测试检查必要文档存在且未被忽略。
- 地址测试允许原始来源地址仅出现在批准的追溯文件中。
- 上游审查单元测试验证从 manifest 读取真实来源仓库和固定提交。
- 重新生成案例与 Skill 数据，运行全量测试、案例校验、构建和 Git 空白检查。
